# Fleet capability batch installation

Use identities as the handoff contract, not copied shell commands or browser
credentials. The Fleet library's DSH target preserves whole-package ownership
for plugin-only components; standalone Skills retain their complete trees and
required MCP dependencies. A URL opens preflight only, never confirms or runs
an Agent. The host fetches the trusted plan and binds installation to its digest.

Acceptance layers: current profile package source → whole catalogue survives
non-installable rows → complete tree/path/hash checks → explicit page click →
effective MCP initialize/tools/list → private credential-free per-item receipt.
Both settings-level and domain-level checks are needed. Wait for the Hub's live
catalogue marker, not merely static visible tabs, before browser selection tests.

Preserve independently installed files/credentials/disabled states by default.
Personal OAuth cannot be replaced with an administrator identity. Copying a
configuration is not proof that native runtime tools have registered; avoid
interrupting running sessions to activate new registrations automatically.

The publisher reader's ZIP/database limits are not a universal archive format.
Do not silently omit assets or execute an unsupported tar.gz installer; name
the format/size blocker, and implement a separately verified adapter if required.

Run `scripts/verify-fleet-batch-browser.py`; confirmation and live Fleet selection
are explicit environment switches documented in the script. It blocks Agent/
Task mutations and can verify both desktop and narrow-screen confirmation.
