## Installed App updates
Added release checks and a dedicated update preview instead of making users add an installed App again. The installer is parsed, never executed. Preview pins a repository revision; owned Skills are staged and replaced with recoverable backups, while other-source conflicts require opt-in.

The publisher moved its declarations from shell variables to Python environment defaults; the old parser rejected the new command. Public MCP endpoints do not necessarily carry authorization headers, and disabled MCPs must not be silently enabled by a content update. Existing configuration is reused for updates; new missing dependencies require a fresh signed command.

42 tests and the build passed. Remote release detection and real preview read the current publisher manifest. The actual content installation was not run. Local networking needed the existing system proxy in the supervised process environment; localhost and vyibc endpoints remain direct. Local runtime has no App receipt, so installation is not inferred merely from existing Skill directories.
